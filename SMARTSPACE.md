# Amanu SmartSpace — первый кандидат Windows

Форк [gsamat/amanu](https://github.com/gsamat/amanu), MIT. Исходный Windows baseline:
`87b3b120278e5d0b10d79ff3355c017d4e52082c` (`codex/ready-0.6.3`, после Windows 0.6.6).
Архив конвейера Сергея использован для исследования архитектуры, его код и настройки
в этот публичный репозиторий не переносились.

## Запуск и экономный профиль

Распакуйте portable в отдельную папку, откройте `Amanu.exe`.
Нужен Windows 11 24H2 x64. .NET и нативные движки уже включены; модели скачиваются
отдельно. Сборка форка не подписана и не устанавливает обновления исходного Amanu.
Первая настройка не включает запись, автозапуск, аналитику или облачные запросы сама.

1. Для экономного профиля выберите локальное распознавание и скачайте модель.
2. В саммари выберите «Свой ключ → Yandex Cloud», сохраните API-ключ сервисного аккаунта.
3. В «Дополнительно → Yandex Cloud» укажите Folder ID, модель, при необходимости словарь.
4. По окончании встречи получите исходную расшифровку и один протокол с решениями,
   задачами, ответственными, сроками и подтверждающими цитатами. Длинный текст
   делится на фрагменты и объединяется существующим механизмом Amanu.

Облако получает текст, локальное распознавание не отправляет аудио. Необходимая роль
для YandexGPT — `ai.languageModels.user`; ключу нужен соответствующий scope доступа.
Проверка ключа при сохранении не делает платных вызовов: правильность проверяется
при обработке выбранной встречи.

## SpeechKit как опция

В расшифровке выберите Yandex SpeechKit: он использует тот же сохранённый ключ и
Folder ID, плюс роль `ai.speechkit-stt.user` и scope распознавания. Режим
`deferred-general` выбран по умолчанию; `general` быстрее. Отложенное распознавание
может занимать до суток. Аудио передаётся непосредственно SpeechKit, без S3,
функций, виртуальных машин и второго сервера.

Микрофон и системный звук выравниваются в стерео, затем делятся на 10-минутные WAV.
Результаты и ID операций сохраняются рядом с записью. Очередь проверяет сохранённый
ID и не блокируется ожиданием одного облачного задания. Принятая операция может
оставаться оплачиваемой после отмены локальной обработки.

Это разделение сторон звонка, а не диаризация отдельных людей внутри канала.
Для SpeechKit/Parakeet/GigaAM автоматическое присвоение имён отключено для всех
агрегированных меток, включая импортированный файл `A`. Для индивидуальных
диаризованных меток самопредставление привязывается к собственной реплике и
сохраняется один раз на встречу; обращения и пересказ чужого представления не
являются доказательством. Ручные имена сохраняются.

Для комнаты или звонка с 3+ индивидуальными голосами следующий отдельный этап —
локальная диаризация с сохранением идентичности между фрагментами. До проверки на
реальной записи этот кандидат не обещает персональную атрибуцию всех участников.

## Приватность и повторы

- Независимые папки `%LOCALAPPDATA%/Amanu SmartSpace Data` и
  `%USERPROFILE%/Amanu SmartSpace Recordings`; исходная установка не мигрируется.
- Ключи — Windows Credential Manager, префикс `Amanu-SmartSpace/`, не `config.json`.
- Yandex вызывается только при явном выборе; не включён в автоматический fallback.
- Фиксированные официальные HTTPS endpoint, перенаправления запрещены, ключи не
  записываются в результаты и ошибки, тело облачной ошибки не показывается.
- YandexGPT отправляет `x-data-logging-enabled: false` согласно документации сервиса.
- Для YandexGPT сохраняются локальные ответы и маркеры запроса в `yandex-requests`.
  После неизвестного результата оплаченного POST автоматический повтор запрещён.
  Маркер снимается при достоверном HTTP-отказе или сохранённом успешном ответе.
  Менять лимит/модель для нового запроса — осознанное действие, которое может стоить денег.
- Для SpeechKit `.speechkit-*.job.json` без ID означает неопределённую отправку.
  Не удаляйте такой файл, пока не проверили, что повтор не создаст платный дубль.
  С известным ID продолжается polling; потерянный/истёкший результат не отправляется заново.
- Локальные кэши содержат текст встреч; учитывайте их при очистке конфиденциальных данных.

## Tracker и другие наши инструменты

Новый daemon и отдельная учётка Tracker не нужны. Используется существующий
`SmartSpace/Knowledge/Инструменты/tracker-sync/src/tracker_sync.py`.

`tools/meeting_tracker_drafts.py` работает без сети и секретов:

```powershell
python tools/meeting_tracker_drafts.py --session C:/Meetings/example --queue SMARTNEW
```

Он читает `summary.md` и `transcript.json`, сверяет дословную цитату и таймкод,
пишет `tracker-drafts.json`. Подтверждённые источником строки экспортируются как
`tracker-proposals/<revision>/<hash>.json` в формате существующего `preview-create`.
ФИО и относительные сроки остаются текстом для проверки человеком; `assignee` и
`deadline` автоматически не назначаются. Маркер в описании помогает найти уже
созданную задачу. Hash стабилен для одинаковой задачи/цитаты в одной записи;
изменённая формулировка или другая встреча требуют отдельной проверки дублей.

Для автоматической подготовки черновиков можно использовать существующий `on_stop`:
он запускается после завершения/пропуска протокола. Пример настройки:

```json
{
  "on_stop": {
    "executable": "C:/Python313/python.exe",
    "arguments": [
      "C:/Users/IgorG/Projects/amanu-smartspace/tools/meeting_tracker_drafts.py",
      "--session", "{session}", "--queue", "SMARTNEW"
    ]
  }
}
```

Этот hook не включён автоматически. Если саммари нет, скрипт завершится с ошибкой;
после ручного пересоздания протокола его запускают заново. Публикация — отдельный
`preview-create`, проверка логинов/даты/очереди/дублей и подтверждённый `apply`.
Идемпотентность `tracker-sync` защищает повторное применение одного плана, но новый
preview той же задачи получит новый ID: сохраняйте соответствие draft → plan → issue.
Внешние задачи в этой подготовке не создавались.

Следующие точки интеграции: привязка объекта к существующей карточке Tracker,
прикрепление протокола к задаче, ссылки на Wiki/Хранилище. Публиковать запись целиком
и добавлять сторонний Telegram relay без отдельного выбора маршрута не требуется.

## Проверка и границы кандидата

Windows managed build/test, fake HTTP контракты и restart/uncertain guards,
локальный экспорт черновиков и native Unicode smoke проверяются без платного API.
Native payload переиспользуется из Windows 0.6.6 с опубликованным SHA-256:
`13affe923a889b3b2faeb5bc300a864e5bf0249de85fb042593fbd640be485f9`.
Нативный код форком не менялся. Его лицензии включены.

Настоящие Yandex API, качество распознавания русской встречи, каналы/таймкоды на
реальном аудио и полная запись совещания пока не проверены. Это кандидат для
контролируемого первого теста, не подтверждённый production-релиз.

Сборка: `windows/scripts/Build-SmartSpace.ps1`; потребуется .NET 10 SDK.
Проверки: `dotnet test windows/Amanu.Windows.slnx`,
`python -m unittest discover -s tools -p 'test_*.py'`.
